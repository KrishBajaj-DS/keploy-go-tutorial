<h2 id="why-keploy">1. Why Keploy for Go Engineers?</h2>

Go engineers value simplicity and reliability. But integration testing in Go often introduces unnecessary complexity:

- **Interface Pollution:** Creating artificial Go interfaces solely to enable mocking with `gomock` or `testify/mock`.
- **Mock Drift:** Hand-written mocks fall out of sync with actual database responses.
- **Flaky Replay:** Time-based fields and random UUIDs cause brittle CI test runs.

<Callout type="tip" title="What Makes Keploy Different">
Keploy intercepts network traffic at the transport layer. Instead of requiring SDK hooks or interface refactoring, it captures raw HTTP requests coming into your app and the outbound database wire protocol calls (like MongoDB's <code>OpMsg</code>) going out — all from outside your application code.
</Callout>

When you replay tests, Keploy acts as a virtual dependency: it re-sends the recorded HTTP requests and intercepts outbound database connections, serving previously recorded responses directly over the socket. No live database required.

<h2 id="sample-app">2. The Sample Application (Gin + MongoDB)</h2>

The quickstart application is a RESTful URL shortener and email verification service built with [Gin](https://github.com/gin-gonic/gin) and the official Go [MongoDB Driver](https://go.mongodb.org/mongo-driver).

### Exposed Endpoints
- **`POST /url`**: Accepts `{"url": "https://example.com"}`, stores it in MongoDB, returns a short code and timestamp.
- **`GET /:param`**: Looks up the short code in MongoDB and issues an HTTP 303 redirect.
- **`GET /verify-email?email=user@domain.com`**: Validates email syntax and domain MX records.

<CodeBlock language="go" filename="main.go (Simplified)">
{`func putURL(c *gin.Context) {
    var req URLReq
    if err := c.BindJSON(&req); err != nil {
        c.JSON(http.StatusBadRequest, gin.H{"error": "Invalid payload"})
        return
    }

    shortCode := generateShortURL(req.URL)
    timestamp := time.Now().UnixNano()

    // Keploy captures this outbound MongoDB write at the wire level
    _, err := collection.InsertOne(context.TODO(), bson.M{
        "url": req.URL, "code": shortCode, "ts": timestamp,
    })

    c.JSON(http.StatusOK, gin.H{
        "url": fmt.Sprintf("http://localhost:8080/%s", shortCode),
        "ts":  timestamp,
    })
}`}
</CodeBlock>

<h2 id="architecture">3. How Keploy Works: Record & Replay</h2>

Understanding how Keploy captures and replays data without code changes is essential.

<ArchitectureDiagram />

### The Two Modes
1. **Record Mode:** Keploy proxies network traffic, capturing incoming HTTP requests and outbound database calls (MongoDB `OpQuery`, `OpMsg`) as YAML test cases and mocks.
2. **Test Mode:** Keploy replays the recorded HTTP requests against your app and intercepts outbound database connections, serving the recorded wire responses instead of hitting a real database.

<h2 id="hands-on-guide">4. Step-by-Step: Running the Quickstart</h2>

### Prerequisites
- Docker Engine installed (I used Docker in WSL2 on Windows)
- Keploy CLI installed ([install guide](https://keploy.io/docs/server/installation/))
- Git

<h3 id="step-1-network">Step 1: Create Docker Network & Start MongoDB</h3>

<Callout type="danger" title="Gotcha: Hostname Case-Sensitivity">
The sample app's <code>main.go</code> connects to <code>mongoDb:27017</code>. The Go Mongo driver normalizes this to lowercase <code>mongodb</code>. Docker's internal DNS treats container names as case-sensitive. If you only name the container "mongoDb", the driver's lowercase lookup fails. Always provide both aliases!
</Callout>

<CodeBlock language="bash" filename="Terminal">
{`# Create a dedicated bridge network
docker network create keploy-network

# Start MongoDB with both casing aliases
docker run -d --name mongodb \\
  --network keploy-network \\
  --network-alias mongodb \\
  --network-alias mongoDb \\
  -p 27017:27017 \\
  mongo`}
</CodeBlock>

<h3 id="step-2-build">Step 2: Clone & Build the Application</h3>

<CodeBlock language="bash" filename="Terminal">
{`git clone https://github.com/keploy/samples-go.git
cd samples-go/gin-mongo
docker build -t gin-app:1.0 .`}
</CodeBlock>

<h3 id="step-3-record">Step 3: Record API Traffic with Keploy</h3>

This is where you launch the app under Keploy's record mode:

<CodeBlock language="bash" filename="Terminal">
{`keploy record \\
  -c "docker run -p 8080:8080 --name MongoApp --rm --network keploy-network gin-app:1.0" \\
  --container-name MongoApp \\
  --build-delay 30`}
</CodeBlock>

<Callout type="warning" title="Auth Blocker I Hit">
On Keploy v3.8.53, running <code>keploy record</code> immediately triggered a browser-based OAuth flow. In my headless WSL2 environment, this timed out after 60 seconds. Neither <code>--in-ci</code> nor setting <code>KEPLOY_API_KEY</code> to a dummy value bypassed it. You will need to authenticate via the Keploy cloud console (free account at app.keploy.io) or use <code>--manual-login</code> in an environment with browser access. See the Troubleshooting section below for the full debugging story.
</Callout>

Once authenticated and recording, send traffic to generate test cases:

<CodeBlock language="bash" filename="Generate Traffic">
{`# 1. Create a shortened URL
curl -X POST http://localhost:8080/url \\
  -H "Content-Type: application/json" \\
  -d '{"url":"https://google.com"}'

# Example response:
# {"ts":1718943885198315028,"url":"http://localhost:8080/Lhr4BWAi"}

# 2. Test the redirect
curl -i http://localhost:8080/Lhr4BWAi
# HTTP/1.1 303 See Other
# Location: https://google.com`}
</CodeBlock>

Stop recording with `Ctrl+C`. Keploy creates test definitions and wire mocks in the `keploy/` directory.

<h3 id="step-4-replay">Step 4: Replay Tests (Zero Database Dependency)</h3>

<CodeBlock language="bash" filename="Terminal">
{`# Stop MongoDB to prove mock isolation
docker stop mongodb

# Replay with Keploy
keploy test \\
  -c "docker run -p 8080:8080 --name MongoApp --rm --network keploy-network gin-app:1.0" \\
  --container-name MongoApp \\
  --delay 10`}
</CodeBlock>

In test mode, Keploy intercepts the app's outbound MongoDB connections and serves pre-recorded BSON responses from `mocks.yaml`. The application runs as if MongoDB is live — but it's entirely simulated.

<h2 id="anatomy">6. Anatomy of Keploy Artifacts</h2>

Let's examine the real generated files from the `samples-go/gin-mongo` repository's `keploy/test-set-0/` directory.

### The Test Case (`test-1.yaml`)

<CodeBlock language="yaml" filename="keploy/test-set-0/tests/test-1.yaml">
{`version: api.keploy.io/v1beta1
kind: Http
name: test-1
spec:
    metadata: {}
    req:
        method: POST
        proto_major: 1
        proto_minor: 1
        url: http://localhost:8080/url
        header:
            Accept: '*/*'
            Content-Length: "33"
            Content-Type: application/json
            Host: localhost:8080
            User-Agent: curl/7.88.1
        body: |-
            {
              "url": "https://google.com"
            }
        timestamp: 2024-06-21T09:54:45.17856559+05:30
    resp:
        status_code: 200
        header:
            Content-Length: "65"
            Content-Type: application/json; charset=utf-8
            Date: Fri, 21 Jun 2024 04:24:45 GMT
        body: '{"ts":1718943885198315028,"url":"http://localhost:8080/Lhr4BWAi"}'
        status_message: OK
    assertions:
        noise:
            body.ts: []
            header.Date: []`}
</CodeBlock>

<Callout type="info" title="Why Noisy Fields Matter">
Notice <code>assertions.noise</code>: Keploy marks <code>body.ts</code> and <code>header.Date</code> as noisy. Without this, every test replay would fail because the timestamp from <code>time.Now().UnixNano()</code> naturally differs on each run.
</Callout>

### The Database Wire Mock (`mocks.yaml`)
Unlike traditional mocks that simulate application-level structs, Keploy captures raw BSON wire packets exchanged with the MongoDB driver.

<CodeBlock language="yaml" filename="keploy/test-set-0/mocks.yaml (Excerpt)">
{`version: api.keploy.io/v1beta1
kind: Mongo
name: mock-1
spec:
    metadata:
        operation: '{ OpMsg flags: 0, sections: [{ SectionSingle msg:
          {"update":"url-shortener","ordered":true,...,"$db":"keploy"} },
          { SectionSingle identifier: updates, msgs: [
            {"q":{"_id":"Lhr4BWAi"},
             "u":{"$set":{"_id":"Lhr4BWAi",
               "created":{"$date":{"$numberLong":"1718943885178"}},
               "url":"https://google.com"}},
             "upsert":true} ] }] }'
    requests:
        - header:
            length: 301
            requestId: 5
            responseTo: 0
            Opcode: 2013  # OpMsg
          message:
            flagBits: 0
            sections:
                - '{ SectionSingle msg: {"update":"url-shortener",...} }'
    responses:
        - header:
            length: 112
            requestId: 6
            responseTo: 5
            Opcode: 2013`}
</CodeBlock>

Key observation: the mock stores the actual MongoDB `OpMsg` operation, including the `upsert` command for the short code `Lhr4BWAi`. During replay, Keploy matches incoming BSON requests against this mock and returns the recorded response bytes directly on the TCP socket.

<h2 id="devrel-takeaways">8. Key Takeaways for Go Teams</h2>

1. **Zero Code Refactoring:** Keploy captures network traffic externally — no need to create test-only interfaces or inject mock dependencies into your Go code.
2. **Wire-Level Fidelity:** Mocks are recorded at the BSON wire protocol level, not at the application abstraction layer. This captures exactly what the database driver sends and receives.
3. **Noise Handling:** Dynamic fields like timestamps and dates are automatically flagged so tests don't flake on every run.
4. **Real-World Friction:** The v3.x CLI requires cloud authentication, which can block headless CI setups. This is worth knowing before adopting Keploy in automated pipelines — plan for API key provisioning.
5. **Docker Networking Matters:** Small details like hostname casing can cause subtle DNS resolution failures in container networks. Keploy doesn't change this — understanding your Docker networking is still essential.
